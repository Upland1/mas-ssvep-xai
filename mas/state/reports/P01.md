## 1. What this phase reproduces

First module of the original project: read the binary EBR format directly (roadmap P01, "Origin") [2]. The questions: does a parser written from `01_DATA_SPEC.md` §2 give the same inventory as the P00 memory-mapped reader, and are configuration v1 (PO7 hard-excluded, legacy) and the legacy zero-phase Butterworth band-pass in place for P02 [1, 2]. No accuracy is involved.

## 7. Interpretation

- Conclusive: on the 10 delivered files the parser, in default and strict mode, reproduces the P00 inventory exactly, and all 10 headers satisfy the strict checks (so no delivered header repeats a key, and the `_1..n` numbering, magic and block size are as §2 states) [7, 9].
- Not conclusive: the 13 absent sessions, and any future cohort. Strict mode also rejects a repeated *unknown* key, which §2 would ignore; this is loud, and the stop/blocker rule of `decisions.md` applies [7, 11].
- The legacy PO7 exclusion is only a config fact in P01; the parser returns 11 channels and `extract_scalp_signal` with the v1 list returns 7 (`04_tests.md`) [5]. The `fs=250` assumption is not in P01 code: `fs` comes from the header (float) and is a required argument of the filter.

## 9. Deviations, decisions, open questions

**Legacy behaviour.** Config v1 hard-excludes PO7 (7 scalp channels), labelled `# PO7 hard-excluded (legacy)` (PF-05, era A). It stays reachable after P07 through git (tag `p01-done`). The reviewer marked it LEGACY (by design) [7].

**Accepted deviations** (signed in the results review; `mas/state/decisions.md`, P01 rows) [7, 11]:
1. `load_ebr_file(path, strict=True)` default; strict adds magic, `_1..n` list numbering, any repeated header line (unknown keys included) and trailing-byte checks. The inventory uses `strict=False` by default and `strict=True` with `--strict`.
2. Extra public parser names (`read_ebr_header`, `open_ebr_block`, `block_shape`, `trailing_bytes`, `ebr_dtype`) for the P00 inventory names; the 14-key contract is unchanged.
3. Stricter helper errors (duplicate names, duplicated MARK, complex data, `nt`/`nb` ≠ 1).
4. Exact `data_type` match (case and space sensitive) in both modes.
5. Header count defaults `trials = bands = 1`, `comments = marks = 0`.
6. Inventory reads whole files (about 136 MB), `--raw-dir` default from config, `--strict` flag off by default.
7. Plan amendment: strict pass and sha256 check added to the run.

Other decisions: `resolve_recording_path` semantics (`session` = subject folder, `filename` = run file, `.ebr` suffix added to a bare stem; Sebastian's Q1 unanswered, plan default kept); if `--strict` fails on a delivered file the runner stops and nobody relaxes the checks (did not occur) [11].

**Open items.** Test gaps listed in `04_tests.md`: header-size cap, negative counts, missing `end_header`, some helper errors (partly covered by smoke tests) [5]. The strict repeated-line check on unknown keys may need limiting to §2 keys if a future file trips it [7]. Blocker B005 stays as in P00; B003 (cohort) unaffected.

**Review rounds.** Pre-run audit Round 1: **FAIL** (`1aa8cf6`). (i) The planned run read only with `strict=False`, so the default mode `load_ebr_file(path)` that P02 will use was never exercised on real headers; fixed by the `--strict` flag, its tests and a plan amendment adding the strict run. (ii) A committed handoff (`00_assignment.md:6`) named a local tool instruction file; fixed by citing `mas/01_DATA_SPEC.md` §2 and `mas/02_REQUIREMENTS.md` §3. Round 2: **PASS** (`4775509`) [7].
