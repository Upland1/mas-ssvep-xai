## 1. What this phase reproduces

Roadmap P08 origin: "try other neural network architectures"; the first network of the original project [1]. Its S03 accuracy is recorded with the device stated, as a legacy diagnostic.

**Max-norm.** Applied to the depthwise spatial filters only (`self.spatial`, `eegnet.py:32`). Each output filter's L2 norm over the channel axis is clipped to 1.0 with its direction kept (`eegnet.py:58–63`). It is applied once after construction and after every optimizer step (`eegnet_cv.py:60, 70`). Other layers are unconstrained. The docstring says this equals the constraint of the original EEGNet implementation (`eegnet.py:9–11`); no source was opened to verify that equivalence [16], so the post-step renorm is recorded as `[own]` [14].

**Training convention (roadmap P08.2 [1]; `eegnet_cv.py:29–93`; `benchmark_eegnet.py:94–108`).**
- Input: per window and per channel, `(x − mean_t) / (std_t + 1e-6)` over the window's own samples (`eegnet_cv.py:32–37`). No other window is used (R2 [2]).
- AdamW, lr 1e-3, weight decay 1e-2; CosineAnnealingLR, T_max = 150, eta_min 1e-5, stepped per epoch; CrossEntropyLoss, label_smoothing 0.05; batch 32 (`eegnet_cv.py:23–27, 54–56, 59`).
- `torch.manual_seed(seed + fold)` immediately before each fold's model (seed 42, folds 42–46), and a DataLoader generator seeded with the same value (`eegnet_cv.py:52–57, 89`) [4 PF-28].
- 150 fixed epochs; no validation split, no early stopping, no checkpoint or epoch selection on test rows (`eegnet_cv.py:61–72`). Augmentation off (`--augment off` is the only accepted value, `benchmark_eegnet.py:67`; augmentation is P10 [1]).
- A mini-batch of size 1 is skipped because of BatchNorm (`eegnet_cv.py:64–65`). On S03 it never triggers: the last batches are 29 and 30 rows (`python3 -c "print(157%32, 158%32)"` → `29 30`).
- Train accuracy: eval mode on the un-augmented training fold after the last epoch, mean over folds (`eegnet_cv.py:93`; PF-30 [4]).
- CUDA only: `cudnn.deterministic = True`, `cudnn.benchmark = False` (`benchmark_eegnet.py:118–120`). `use_deterministic_algorithms` is not set.

**Quality gate and folds (legacy, shared with the flagship).** `gated_windows` calls `quality_gate` with `GATE_THRESHOLDS` (vpp 5–120 µV, std 1–35 µV) and `CHANNEL_FAIL_FRACTION` (0.5) on the legacy arrays, and `subject_channel_names` for the names (`benchmark_eegnet.py:83–91`) [13]. The reviewer checked that this is the same decision as the flagship's `prepare_subject` path (R5 row, `07_review.md`) [7]. Folds are `legacy_cv(42)`, the same `StratifiedKFold(5, shuffle, 42)` object as the flagship (`eegnet_cv.py:19, 88`) [12, 7]. The gate is the P07 two-tier gate, unchanged in P08 (`mas/state/reports/P07.md` §2) [15].

**CLI.** `--subject` (default S03), `--subjects`, `--epochs` (150), `--batch-size` (32), `--lr` (1e-3), `--device {auto,cpu,cuda}`, `--augment {off}`, `--seed` (42), `--config`, `--data-root`/`--processed-dir`, `--reports-dir` (`benchmark_eegnet.py:59–73`) [13].

### 4.4 CPU–CUDA gap

- Gap: 149 − 140 = 9 windows at 1.0 s; 169 − 160 = 9 windows at 2.0 s (`python3 -c "print(149-140, 169-160)"`). In percentage points from the CSV: 75.63 − 71.07 = 4.56 and 85.79 − 81.22 = 4.57.
- Per-fold difference CPU − CUDA in test windows: −1, +1, 0, +3, +6 (sum 9). Fold 4 carries 6 of 9 (`python3 -c "print(6/9)"` → `0.667`).
- Scale: the binomial SE of one accuracy near p = 0.73 with n = 197 is 3.16 pp (`python3 -c "import math; print(round(100*math.sqrt(0.73*0.27/197),2))"`). 4.57 / 3.16 = 1.44. This is a scale reference only: the two devices score the same windows, so the difference is paired and this is not its standard error.
- Reading: the two devices give different numbers, each reproducible (§4.3). The mechanism (floating-point order in the kernels, or other) was not isolated by a test. The gap is a device-associated difference, not run-to-run nondeterminism and not a model effect [7, 5]. Neither device's number is "the" P08 result; they are not averaged. Later A/B comparisons use one fixed device (CPU, as decided for P04) and fixed seeds, and treat differences of a few windows as noise [5].

## 7. Interpretation

- **Conclusive.** EEGNet trains and evaluates on CPU and on CUDA (4 of 4 runs exit 0). Its parameter count is R-8's 2,349 on both devices, and the S03 gate counts (197 / 3, 7 channels) equal the classical flagship's. Each device repeats itself exactly over two runs on this machine (§4.3).
- **Accuracy level.** Not conclusive as a model property. The protocol is leaky: five 1 s windows of one trial can fall in train and test (PF-01 [4]). The S03 result is one subject, one configuration, no augmentation, and one seed set.
- **CPU–CUDA difference.** A device-associated difference of 9 windows on both metrics, about 1.4 times the binomial scale of §4.4. Later A/B comparisons must fix the device and the seeds (PF-28 [4]).
- **PF-30 reading (train versus test).** Final training accuracy is 98.34 % (cpu) and 98.60 % (cuda), above the pre-committed expectation of about 95 % [7]. Test accuracy is 75.63 % and 71.07 %, well above chance (20 % for five classes). Following PF-30 [4]: high training accuracy with a large train-test gap is a generalization problem, not an optimization problem. The gap is 22.71 pp (cpu) and 27.53 pp (cuda) (`python3 -c "print(round(98.34-75.63,2), round(98.60-71.07,2))"`). Leaky CV inflates test accuracy, so a leak-free test accuracy would be lower and the gap larger. This is a reading to be measured in P11, not a result. Fold 1 is the hardest on both devices (55.00 % / 52.50 % test at 96.18 % / 97.45 % train).
- **Leaky EEGNet versus leaky flagship.** On S03 the leaky EEGNet is 19 to 38 windows below the leaky flagship (178 / 188 of 197). PF-01 predicts that leaky CV inflates CNNs more than LDA; here no CNN advantage appears under this leak. This is a single-subject observation, not a ranking.
- **Smoothing caveat.** The 2.0 s figure is the legacy i%5 average over the condition-ordered clean array (PF-02 [4]). S03's three rejected windows shift the 5-blocks, so some pairs average windows of adjacent trials. The gain of +20 windows on both devices (149 → 169; 140 → 160; `python3 -c "print(169-149, 160-140)"`) is a legacy-rule figure, not a measured 2 s decision accuracy.
- **Inputs.** fs 250 is a label only (EEGNet does not use it). Input is the z-scored legacy 7-channel window, not PSD or band features.
