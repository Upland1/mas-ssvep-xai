## 1. What this phase tests

Roadmap P16 origin, from the professor's change list: research edge effects; filter the raw continuous signal instead of each window; use only valid windows in frequency analyses; and the recordings are **256 Hz**, not the 250 Hz assumed in feature code [1]. Questions:

- **Edge effects (Task 3).** How large is the error of per-window sub-band filtering at the first and last 100 ms, against the centre, for every FBCSP and FBCCA band? [1, 7]
- **Era C data path (Tasks 2, 4–6).** One window index with true trial ids, continuous zero-phase filtering before cutting, one shared quality decision with an artifact guard, fs from metadata, one loader [1, 2].
- **Baseline freeze and regression (Tasks 1, 7; blocking).** The frozen v1 snapshot is read-only, and the ported scripts on the legacy root reproduce v1 exactly (flagship R-6; connectivity P13 final) [1, 2].
- **v1 → v2 decomposition (Task 8).** Which part of the change from v1 to v2 is due to fs, to the filtering mode, to the guard, and to the smoothing rule and the build [1, 2].

Acceptance, verbatim from the assignment [1]: "snapshot exists and is read-only; edge-effect table shows edge error ≫ centre error for narrow FBCSP bands; `stride=None` per_window build reproduces the legacy window starts; v1/v2 table complete with every number backed by a log. No fixed numeric target for v2 (none was preserved — see R-16); the Reviewer must explain the direction of every change."

Pre-committed criteria, fixed by the reviewer before any number of the run existed [7]: (1) edge criterion: for each narrow band (7–12, 13–17, 18–26 Hz) edge/centre ratio ≥ 5 **and** edge error ≥ 20 %, and every band with edges > centre; the ≥ 10 reading is information only. ### 4.1 Historical facts (R-16) and the change from v1 to v2

The two facts that R-16 requires in this report [4]:

- **v1 used fs = 250 in feature code on 256 Hz recordings.** The recording header gives fs 256 Hz in every build log (`fs 256 Hz (header)`, `reports/logs/P16/04_scripts.build_windows.log`). The legacy feature path assumes 250 Hz: the FBCCA references are built with `t = n / fs` at fs 250 (`07_review.md`, pre-run audit, the reviewer's reading of `fbcca_extraction.py:35–41`) [7, 10]. The v1 frozen run is therefore a fs-250 result [4, 7].
- **v1 filtered sub-bands per 1 s window.** The legacy FBCCA path filters each sub-band on each window (`compute_fbcca_correlations(window, fs=250, …)`, decisions.md P04 row 41) [5]. The legacy FBCSP path filters per window too (the P05 extractors; R3 legacy) [3, 7]. The continuous build filters the whole recording and then cuts (`band_windows`, mode `continuous`, `src/preprocessing/windowing.py:220`) [7].

The v2 numbers are the first computed with the real sampling rate (256 Hz, from metadata) and continuous filtering. R-6 (P11, leak-free, fs 250, per-window filtering, seven channels) stays the P11 target and is not a target for v2 [3, 4].
